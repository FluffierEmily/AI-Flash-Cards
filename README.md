# AI-powered Flash Cards

A highly customizable, modern offline-first Single Page Application (SPA) and Progressive Web App (PWA) designed to supercharge learning through spaced repetition and intelligent, AI-driven answer scoring and card creation.

## 🛠️ Tech Stack
- **Frontend Framework:** React (SPA)
- **Build System:** Vite
- **PWA Support:** `vite-plugin-pwa` (offline asset caching, custom service worker, and web app manifest)
- **Styling:** shadcn/ui (React components built with Tailwind CSS & Radix UI for premium, customizable, and accessible aesthetics)
- **Package Manager:** `pnpm`
- **AI Integration:** Vercel AI SDK (unified, type-safe client-side LLM calls and structured feedback generation)
- **Push Notifications:** Firebase Cloud Messaging (FCM) (configured via service worker and Bring Your Own Project)
- **Local Storage:** IndexedDB (for high-performance offline-first local data storage)

## ✨ Core Features
1. **AI-Generated Scoring & Feedback**
   - Traditional flashcards rely on binary self-grading (e.g., "Got it" / "Forgot it").
   - This app supports free text or spoken answers scored by AI (via Gemini/LLM) for accuracy and completeness.
   - Score influences SRS: NextInterval and EaseFactor.
   - Contextual feedback highlighting what was right, what was wrong, and suggestions for improvement.
   - Bring Your Own Key (BYOK) support
2. **Spaced Repetition System (SRS)**
   - Algorithmic scheduling (SM-2 or similar) to present cards at optimal intervals based on your past score history.
   - Automatically adapts to your pace and custom difficulty levels.
3. **Offline-First & Data Portability**
   - **PWA Installability & Offline Cache:** Can be installed directly onto desktop or mobile home screens. Assets, routes, and UI are fully cached offline via Service Worker.
   - **Local IndexedDB Database:** All flashcard decks, study history, and SRS intervals are stored entirely locally in your browser.
   - **CSV Export & Import:** Full support for exporting and importing your card decks as CSV files for easy backups, edits in spreadsheet tools, or migrating decks.
4. **Independent Push Notifications**
   - System-level browser notifications using Firebase Cloud Messaging (FCM) to alert you when reviews are due, even if the app is closed.
5. **High Customizability**
   - Create custom card types with custom AI eval prompts.
   - Support markdown formatting and code snippets with syntax highlighting in the most common programming languages and CLI scripts.
6. **Quality of Life Features**
   - Sleek modern minimalist design with responsive layouts and smooth, but snappy card-flipping/swipe transitions.
   - Keyboard shortcut support for quick, friction-free study sessions.

## 🚀 Getting Started

### 📋 Prerequisites
- [Node.js](https://nodejs.org/) (v24 or higher)
- [pnpm](https://pnpm.io/) (`npm install -g pnpm`)

### ⚙️ Installation & Setup

1. **Clone the Repository:**
   ```bash
   git clone https://github.com/FluffierEmily/AI-Flash-Cards.git
   cd AI-Flash-Cards
   ```

2. **Install Dependencies:**
   ```bash
   pnpm install
   ```
   *Note: If build scripts are ignored during installation, run `pnpm approve-builds --all`.*

3. **Start Development Server:**
   ```bash
   pnpm run dev
   ```

4. **Build Production Application:**
   ```bash
   pnpm run build
   ```

## 🔔 Firebase Cloud Messaging (FCM) Setup

To configure system-level push notification reminders for card reviews (even when the app is closed):

1. Go to the [Firebase Console](https://console.firebase.google.com/) and click **Create a project**.
2. Register a new **Web App** in your project dashboard.
3. Go to **Project Settings &rarr; Cloud Messaging** tab.
4. Under the **Web configuration** section at the bottom, find **Web Push certificates** and click **Generate Key Pair**. This is your Web Push VAPID Public Key.
5. Launch the AI Flash Cards application, and click the **Bell Icon** in the top navigation bar to open the FCM Setup drawer.
6. Paste the configuration block generated by Firebase (or input the fields manually) along with the VAPID Public Key.
7. Click **Enable Push & Save Config** and approve browser notification permissions.
8. Your unique **FCM Registration Token** will be generated and displayed. Copy it to send test notifications to your browser!

## ⏰ Scheduling Background Reminders (Cloud Functions + Cloud Tasks)

Since client-side PWAs cannot execute background schedules when closed or securely store private Firebase Admin credentials, scheduling future review alerts is accomplished by linking your Firebase project with **Google Cloud Functions** and **Cloud Tasks**.

### 1. Enable Firebase Blaze Plan
Google Cloud Tasks and Cloud Functions v2 require your Firebase project to be on the **Blaze (Pay-as-you-go) Plan**. 
*Note: The free tier limits are very generous (e.g., 100,000 tasks/month free for Cloud Tasks).*

### 2. Initialize Firebase Functions
Run the following commands in your local shell to scaffold a Firebase Functions environment:
```bash
# install firebase tools
npm install -g firebase-tools

# Log in to your Firebase account
firebase login

# Initialize Functions in the project root directory
firebase init functions
```
- Select your existing Firebase project.
- Choose **JavaScript**
- Allow it to install dependencies using `npm`.

### 3. Install Google Cloud Tasks Client
Navigate to your new `functions/` folder and install the Cloud Tasks SDK:
```bash
cd functions
npm install @google-cloud/tasks firebase-admin
```

### 4. Create a Cloud Tasks Queue

You need to create a queue named `fcmRemindersQueue` inside your Google Cloud project (which matches your Firebase project ID). You can do this either via the **Google Cloud CLI** or using the **Google Cloud Web Console**.

#### Method A: Cloud Web Console
1. Open the [Google Cloud Tasks Console](https://console.cloud.google.com/cloudtasks).
2. Select your Firebase project in the top navigation project selection dropdown.
3. Click **Enable** if prompted to activate the Cloud Tasks API.
4. Click **Create Queue** at the top of the panel.
5. Define the queue properties:
   - **Queue ID**: `fcmRemindersQueue`
   - **Location**: `europe-west1`
6. Click **Create** to save.

#### Method B: Local gcloud CLI
1. Download and run the installer (as admin) for your OS from the [Google Cloud CLI Install Page](https://cloud.google.com/sdk/docs/install).
2. Open a new terminal (as admin) and initialize the CLI to log in and select your project:
   ```bash
   gcloud init
   ```
3. Enable the Cloud Tasks API on your project:
   ```bash
   gcloud services enable cloudtasks.googleapis.com
   ```
4. Create the task queue in the Frankfurt region (`europe-west3`):
   ```bash
   gcloud tasks queues create fcmRemindersQueue --location=europe-west3
   ```

### 5. Deploy the Functions
Deploy your backend logic to Firebase:
```bash
firebase deploy --only functions
```
Once deployed, copy the HTTPS trigger URL for `scheduleReminder` (e.g., `https://europe-west3-your-project-id.cloudfunctions.net/scheduleReminder`).

## 💻 Development

### 🧪 Testing Locally with the Firebase/Cloud Functions Emulator

To test the functions locally before deploying them, you can run the Firebase Emulator Suite.

#### A. Setup Private Key for Real FCM Notification Sending (Optional)
By default, the functions emulator does not have credentials to send real FCM notifications. If you want to receive actual push notifications on your devices when testing locally:
1. Go to the [Firebase Console](https://console.firebase.google.com/).
2. Select your project, and navigate to **Project Settings** &rarr; **Service accounts** tab.
3. Click **Generate new private key** and download the JSON file.
4. **Important**: Save this file outside of your git repository, or ensure it is added to your `.gitignore`. For example, save it as `service-account.json` in a directory outside the repository or inside `functions/` and add it to `functions/.gitignore`.
5. Set the `GOOGLE_APPLICATION_CREDENTIALS` environment variable in your terminal before running the emulator:
   - **Windows (PowerShell)**:
     ```powershell
     $env:GOOGLE_APPLICATION_CREDENTIALS="path/to/service-account.json"
     ```
   - **macOS/Linux (Bash)**:
     ```bash
     export GOOGLE_APPLICATION_CREDENTIALS="path/to/service-account.json"
     ```

#### B. Start the Emulator Suite
From the repository root, start the Firebase Emulators:
```bash
firebase emulators:start --only functions
```
This boots up the Cloud Functions emulator (normally hosted at `http://127.0.0.1:5001`).

#### C. Triggering Local Tests
You can trigger the HTTP functions locally using standard tools like `curl` or PowerShell. Replace `<your-project-id>` with your Firebase project ID and `<your-fcm-token>` with your device's FCM Registration Token (retrieved from the application's FCM Setup drawer).

##### 1. Immediate Notification (`sendPushNotification`)
- **PowerShell**:
  ```powershell
  Invoke-RestMethod -Uri "http://127.0.0.1:5001/<your-project-id>/europe-west1/sendPushNotification" `
    -Method Post `
    -ContentType "application/json" `
    -Body '{"fcmToken":"<your-fcm-token>", "title":"Emulator Test", "body":"Hello immediately from the local emulator!"}'
  ```
- **cURL**:
  ```bash
  curl -X POST -H "Content-Type: application/json" \
    -d '{"fcmToken":"<your-fcm-token>", "title":"Emulator Test", "body":"Hello immediately from the local emulator!"}' \
    http://127.0.0.1:5001/<your-project-id>/europe-west1/sendPushNotification
  ```

##### 2. Scheduled Notification (`scheduleReminder`)
This schedules a task in the local emulator's queue, simulating the delay.
- **PowerShell**:
  ```powershell
  # Schedule task 10 seconds from now
  $sendAt = [DateTimeOffset]::UtcNow.AddSeconds(10).ToUnixTimeMilliseconds()
  Invoke-RestMethod -Uri "http://127.0.0.1:5001/<your-project-id>/europe-west1/scheduleReminder" `
    -Method Post `
    -ContentType "application/json" `
    -Body (@{ fcmToken="<your-fcm-token>"; sendAtTimestamp=$sendAt; title="Scheduled Emulator Test"; body="Hello after 10 seconds from the local emulator!" } | ConvertTo-Json)
  ```
- **cURL**:
  ```bash
  # Calculate Unix timestamp for 10 seconds from now (macOS/Linux)
  SEND_AT=$(($(date +%s)*1000 + 10000))
  curl -X POST -H "Content-Type: application/json" \
    -d "{\"fcmToken\":\"<your-fcm-token>\", \"sendAtTimestamp\":$SEND_AT, \"title\":\"Scheduled Emulator Test\", \"body\":\"Hello after 10 seconds from the local emulator!\"}" \
    http://127.0.0.1:5001/<your-project-id>/europe-west1/scheduleReminder
  ```

Check the terminal window running `firebase emulators:start` to verify the execution logs, task enqueuing, and success/error status messages!
